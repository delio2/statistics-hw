Homework 5 - Riemann and Lebesgue integration, numerical computation of the normal CDF

Exercise 1: numerical integration with a Riemann-type sum and a Lebesgue-type sum, and their comparison. Exercise 2: an efficient method for the standard normal CDF, compared with a reference from the web. With the code.

Exercise 1 - Riemann and Lebesgue integration

The two numerical approaches, for a function f ≥ 0 on [a, b] (all the functions below are non-negative):

  • Riemann. Partition the domain [a, b] into N equal subintervals and add f(xi) × width, where xi is the midpoint of the i-th subinterval.
  • Lebesgue. Partition the range [0, M], where M is the largest value of f, into K equal levels Ej = [yj−1, yj), with yj = jM/K (the last level also contains M), and add yj−1 × λ(f−1(Ej)), where λ is the length (the Lebesgue measure) of the preimage of Ej in the domain. It is the integral of a step function below f, so it is a lower sum. The length of a preimage cannot be computed exactly for a general f: it is measured on the same grid of N subintervals, as the total width of the subintervals whose midpoint value lies in Ej.

The code (js/integrals.js):

// Riemann: partition [a, b] into N equal subintervals and add f(midpoint) * width
function riemann(f, a, b, N) {
  const dx = (b - a) / N;
  let sum = 0;
  for (let i = 0; i < N; i++) sum += f(a + (i + 0.5) * dx);
  return sum * dx;
}

// Lebesgue (f >= 0): partition the range [0, M], M = largest value, into K equal levels
// E_j = [y_(j-1), y_j), y_j = j M / K, and add y_(j-1) * (measure of the preimage of E_j).
// The preimage is measured on the grid of the domain: the total width of the N subintervals
// (the same as above) whose midpoint value lies in E_j. The last level also contains M
function lebesgue(f, a, b, N, K) {
  const dx = (b - a) / N, values = new Float64Array(N);
  let M = 0;
  for (let i = 0; i < N; i++) { values[i] = f(a + (i + 0.5) * dx); if (values[i] > M) M = values[i]; }
  const h = M / K, measure = new Float64Array(K);
  for (let i = 0; i < N; i++) measure[Math.min(K - 1, Math.floor(values[i] / h))] += dx;
  let sum = 0;
  for (let j = 0; j < K; j++) sum += j * h * measure[j];
  return sum;
}

Both sums use the same N values f(xi). The Lebesgue sum adds each of them after rounding it down to a level boundary yj: grouping the values by level changes how the sum is organised, not which values enter it.

Numerical results

The functions f1, ..., f7 are the seven examples of the exercise. Their integrals are known analytically (for f7 it is Si(π) = 1.8519370519824662...), so the error of a numerical value can be computed.

I use N = 11, 101, 1,001, 10,001 and 100,001 subintervals, and K = N levels. N is odd so that the jump at x = 0.5 of the two step functions falls inside a subinterval (on a subinterval boundary their Riemann sums would be exact by chance). The tables show the error |numerical value − exact integral|. The last column is the observed order p, error ~ N−p, between N = 10,001 and N = 100,001. The midpoints never fall on x = 0, where f5 is infinite and f7 is 0/0.

Accuracy. For the same N the Riemann sum is more accurate than the Lebesgue sum in every row of the tables. The Lebesgue sum has the same error as the Riemann sum plus the error of rounding the values down to the levels, which is always downwards and about (b − a) M/(2K) on average: for f1 = sin x with N = K = 100,001 it is π/(2 · 100,001) = 1.6 · 10−5, which is the error in the table, while the Riemann error is 8 · 10−11.

Convergence. The Riemann (midpoint) sum has order p = 2 for the smooth functions f1, f2 and f7, and for f4 = |x − 0.5|, whose corner at 0.5 is a midpoint when N is odd. It has order 1 for the two step functions f3 and f6: only the subinterval that contains the jump gets a wrong value, and the error is half the jump times the width of a subinterval (1/N for f3, −1/(2N) for f6). It has order 1/2 for the unbounded f5 = 1/√x: the error is about 0.605/√N, almost all of it from the first subintervals. The Lebesgue sum is dominated by the rounding to the levels, which is of order 1 in K for every bounded function, whatever its smoothness; so it does not profit from smoothness, and the two step functions behave like the others. For f5 the largest value is M = √(2N), which grows with N, and the order drops to 1/2.

Computational efficiency. The Riemann sum needs N evaluations of f and nothing else: time O(N), memory O(1). The Lebesgue sum also needs N evaluations of f, but the levels exist only when M is known, so the N values are stored (or f is evaluated twice), then each value is assigned to a level and the K measures are accumulated and added: time O(N + K) and memory O(N + K); the time table, for the same N = K, shows that it is slower. More important is the accuracy per unit of cost: for f1 the Riemann sum with N = 1,001 (error 8.2 · 10−7) is more accurate than the Lebesgue sum with N = K = 100,001 (error 1.6 · 10−5), which costs about 100 times more.

Do they converge to the same value? For the Riemann-integrable functions (f1, f2, f4 and f7 are continuous, f3 and f6 are bounded with one jump) the two sums converge to the same value, the integral: the errors go to 0 along every row of both tables. This is expected, because a Riemann-integrable function is also Lebesgue integrable and the two integrals are equal (Rudin, theorem 11.33): the two kinds of sums approach the same number and differ only in the speed. The same holds for the unbounded f5 = 1/√x: it is not Riemann integrable (it is not bounded), but its improper Riemann integral and its Lebesgue integral are both 2, and both sums converge to 2, slowly.

Functions for which the two approaches behave differently

A computer stores only rational numbers (every double is a fraction), so the points where the Dirichlet function and Thomae's function differ cannot be generated and tested: they are described. A rational point is the pair [p, q] = p/q and an irrational point is null (for instance (i − 1 + 1/√2)/N). The Riemann sum has one tag in each of the N subintervals of [0, 1]: either the rational midpoint [2i − 1, 2N], or an irrational point. The code (js/integrals.js):

// The pathological functions. A computer stores only rational numbers, so a point is described,
// not computed: a rational point is the pair [p, q] = p/q, an irrational point is null
const gcd = (p, q) => (q === 0 ? p : gcd(q, p % q));
// Dirichlet: 1 if x is rational, 0 if x is irrational
const dirichlet = (point) => (point === null ? 0 : 1);
// Thomae: 1/q if x = p/q in lowest terms, 0 if x is irrational
const thomae = (point) => (point === null ? 0 : gcd(point[0], point[1]) / point[1]);

// Riemann sum on [0, 1] with N subintervals and one tag in each: the rational midpoint
// (2i - 1)/(2N), or an irrational point
function taggedRiemann(f, N, rational) {
  let sum = 0;
  for (let i = 1; i <= N; i++) sum += f(rational ? [2 * i - 1, 2 * N] : null) / N;
  return sum;
}

Dirichlet function (1 at the rationals, 0 at the irrationals). Every subinterval contains rational and irrational numbers, so the Riemann sum depends on the tags: 1 with rational tags, 0 with irrational tags, for every N. The sums do not converge to a common value: the upper Darboux sum is 1, the lower one is 0, and the function is not Riemann integrable. The Lebesgue approach works: the function takes two values, the preimage of 1 is the set of the rationals of [0, 1], which is countable and has measure 0, the preimage of 0 has measure 1, and the integral is 1 · 0 + 0 · 1 = 0. The numerical Lebesgue sum of the previous section cannot find it: it measures a preimage on the grid, and all the grid points are rational, so it would assign to the preimage of 1 the whole interval, measure 1, and give 1, like the Riemann sum with rational tags. The measure of the preimage must be known exactly, which is a result of measure theory, not of numerical computation.

Thomae's function (1/q at p/q in lowest terms, 0 at the irrationals). It is continuous at every irrational point and discontinuous at the rationals, a countable set of measure 0, so it is Riemann integrable (Lebesgue's criterion) and its integral is 0: for every ε > 0 only finitely many points have f ≥ ε. The Riemann sums converge to 0 for any choice of tags, but irregularly: with the rational midpoint tags the sum is (1/N) Σ gcd(2i − 1, 2N)/(2N), which depends on the prime factors of N (table). The Lebesgue approach gives 0 at once: the preimage of every level above 0 is a finite set, of measure 0. Here both approaches end at the same value, 0: the Lebesgue sum reaches it at once, the Riemann sums with rational tags irregularly.

Exercise 2 - Numerical computation of the normal CDF

The CDF of the standard normal distribution is Φ(x) = ∫−∞x φ(t) dt, where φ(t) = e−t²/2/√(2π) is the density. Because φ is even, Φ(x) = 1/2 + ∫0x φ(t) dt and Φ(−x) = 1 − Φ(x).

The method: a power series for the centre, a continued fraction for the tails

Series, |x| < 3. The function y(x) = ex²/2 ∫0x e−t²/2 dt satisfies y′ = x y + 1 with y(0) = 0, and substituting a power series in this equation gives y = x + x³/3 + x5/(3·5) + x7/(3·5·7) + ... . Since ∫0x φ = φ(x) y(x),

Φ(x) = 1/2 + φ(x) (x + x³/3 + x5/(3·5) + x7/(3·5·7) + ...).

All the terms have the sign of x, and each one is the previous one times x²/(2n + 1): there is no cancellation among the terms, and the series converges for every x. It is used where it needs few terms: at most 34 for |x| < 3.

Tails, |x| ≥ 3. For x > 0 the upper tail Q(x) = 1 − Φ(x) is given by Laplace's continued fraction

Q(x) = φ(x) / (x + 1/(x + 2/(x + 3/(x + ...)))).

It converges faster the larger x is (at most about 50 iterations for x ≥ 3). It is evaluated with the modified Lentz algorithm, which goes forward and stops when an iteration changes the value by less than 10−15 (relative). Then Φ(−x) = Q(x) and Φ(x) = 1 − Q(x). The tail is computed directly and not as 1 − Φ(x): the doubles just below 1 are 1.1 · 10−16 apart, so a probability such as Φ(−8) = 6.2 · 10−16 would keep at most one digit.

The code (js/normcdf.js); series and tail also return the number of terms or iterations, used in the tables below:

const SQRT_2PI = Math.sqrt(2 * Math.PI);

// density phi(x) = exp(-x^2 / 2) / sqrt(2 pi)
const density = (x) => Math.exp(-x * x / 2) / SQRT_2PI;

// Series, |x| < 3: Phi(x) = 1/2 + phi(x) (x + x^3/3 + x^5/(3*5) + x^7/(3*5*7) + ...).
// All the terms have the sign of x, so there is no cancellation among them.
// Returns the value and the number of terms that were added
function series(x) {
  let term = x, sum = x, n = 0;
  while (Math.abs(term) > 1e-17 * Math.abs(sum)) { n++; term *= x * x / (2 * n + 1); sum += term; }
  return { value: 0.5 + density(x) * sum, terms: n + 1 };
}

// Tail, x >= 3: Q(x) = 1 - Phi(x) = phi(x) / (x + 1/(x + 2/(x + 3/(x + ...)))),
// a continued fraction evaluated with the modified Lentz algorithm.
// Returns the value and the number of iterations
function tail(x) {
  let f = x, C = x, D = 0, k = 1;
  for (; k <= 1000; k++) {
    D = 1 / (x + k * D);
    C = x + k / C;
    const delta = C * D;
    f *= delta;
    if (Math.abs(delta - 1) < 1e-15) break;
  }
  return { value: density(x) / f, iterations: k };
}

// Phi(x): the series for |x| < 3; for the tails the continued fraction, with Phi(-x) = 1 - Phi(x)
function Phi(x) {
  if (!Number.isFinite(x)) return Number.isNaN(x) ? NaN : (x > 0 ? 1 : 0);
  if (Math.abs(x) < 3) return series(x).value;
  const q = tail(Math.abs(x)).value;
  return x > 0 ? 1 - q : q;
}

Comparison with a reference from the web

The reference is the table of numerical values in the Wikipedia article 68–95–99.7 rule (version of 10 August 2026, read on 11 November 2026). For z = 0.5, 1, ..., 8 it gives the probability P(|Z| ≤ z) = 2Φ(z) − 1 that a standard normal variable Z falls within z standard deviations of the mean, with 15 decimals, and the frequency outside the range as “1 in N”. The reference is rounded, so differences of a few 10−16 are expected.

The largest difference of 2Φ(z) − 1 is : the reference is rounded to 15 decimals (an error up to 5 · 10−16) and the doubles close to 1 are 1.1 · 10−16 apart. The integers N coincide in the 14 rows where the table gives “1 in N” (for z = 0.5 and z = 1.5 it gives the coarse fractions 3 in 5 and 2 in 15, that is 1 in 1.67 and 1 in 7.5, against 1 in 1.62 and 1 in 7.48 computed). For z = 8 the probability outside is about 1.2 · 10−15 and N has 15 digits, all correct: computing the tail directly keeps the digits of a very small probability.

Efficiency and accuracy

Cost. One evaluation costs the number of terms (series) or iterations (fraction) in the table. The series needs more terms as |x| grows, the fraction fewer iterations, and they are about equal at x = 3. The time columns are measured in your browser: the series is cheaper for moderate x, the fraction for large x.

Accuracy on the lower tail Φ(−x) (last column). The series computes it as 1/2 minus a number close to 1/2, so the rounding error of that subtraction, about 10−16, becomes large relative to a small Φ(−x): the two routes differ by about 10−13 at x = 3 and 10−7 at x = 6, and at x = 8 the series has no digit left. The fraction does not subtract, and the comparison with the reference above shows that it reproduces all the digits of the reference (up to 15 digits for z = 8). That is why the tails use the fraction.

The switch at x = 3. There the series has lost about two digits on the lower tail, and it is still cheaper than the fraction.

Other numerical approaches

The exercise suggests numerical integration, series expansions and approximations based on erf. I implemented one of each to compare them with the method above (js/normcdf.js):

// numerical integration of the density from 0 to x with N subintervals, Phi(x) = 1/2 + integral:
// the trapezoidal rule and Simpson's rule (N even)
function trapezoid(x, N) {
  const h = x / N;
  let sum = (density(0) + density(x)) / 2;
  for (let i = 1; i < N; i++) sum += density(i * h);
  return 0.5 + sum * h;
}
function simpson(x, N) {
  const h = x / N;
  let sum = density(0) + density(x);
  for (let i = 1; i < N; i++) sum += (i % 2 ? 4 : 2) * density(i * h);
  return 0.5 + sum * h / 3;
}
// power series of erf: erf(z) = 2/sqrt(pi) * sum_n (-1)^n z^(2n+1) / (n! (2n+1)),
// and Phi(x) = (1 + erf(x/sqrt 2)) / 2. The terms alternate in sign: for large |x| they
// become huge before they decrease, and the sum loses its digits
function erfSeries(z) {
  let term = z, sum = z; // term = (-1)^n z^(2n+1) / n!
  for (let n = 1; n <= 500; n++) {
    term *= -z * z / n;
    sum += term / (2 * n + 1);
    if (Math.abs(term / (2 * n + 1)) <= 1e-17 * Math.abs(sum)) break;
  }
  return 2 / Math.sqrt(Math.PI) * sum;
}
const PhiErfSeries = (x) => 0.5 * (1 + erfSeries(x / Math.SQRT2));

// approximation of erf (Abramowitz and Stegun 7.1.26, |error| <= 1.5e-7),
// and Phi(x) = (1 + erf(x/sqrt 2)) / 2
function erfApprox(z) {
  const t = 1 / (1 + 0.3275911 * Math.abs(z));
  const poly = ((((1.061405429 * t - 1.453152027) * t + 1.421413741) * t - 0.284496736) * t + 0.254829592) * t;
  const y = 1 - poly * Math.exp(-z * z);
  return z >= 0 ? y : -y;

  • Power series of erf (DLMF 7.6.1): erf(z) = (2/√π) Σ (−1)n z2n+1/(n! (2n + 1)), with Φ(x) = (1 + erf(x/√2))/2. The terms alternate in sign and grow up to about ez² before decreasing, so the sum loses up to about z²/ln 10 digits.
  • Approximation of erf (Abramowitz and Stegun 7.1.26): erf(z) ≈ 1 − (a1t + ... + a5t5) e−z², t = 1/(1 + 0.3275911 z), for z ≥ 0, with an error of at most 1.5 · 10−7: one exponential and a polynomial.

Results. The trapezoidal rule with N = 1000 has an error of 7 · 10−8 on the 16 points and Simpson's rule 7 · 10−14: the first is of order h², the second of order h4. Both need 1,001 evaluations of the exponential for each value, much more time than the series and the fraction (time column), whose error is below 10−15, that is the rounding of the reference. The erf series is accurate for small |x|, but for z = x/√2 up to 5.7 its terms grow to about e32, roughly 1014, before decreasing, and its largest error is 1.4 · 10−4. The approximation of erf is the fastest and has the advertised accuracy, 1.4 · 10−7 (the bound is 1.5 · 10−7): seven digits only.

Why Φ is not an elementary function

The elementary functions are those obtained from the variable and from constants with finitely many sums, products, quotients, compositions, roots of polynomial equations, exponentials and logarithms. Since Φ′ = φ, Φ is elementary exactly when an antiderivative of φ is (two antiderivatives differ by a constant). The result behind the fact is Liouville's theorem (1835), in the special case that concerns exponentials, as stated by Marchisotto and Zakeri (1994, p. 300):

if f and g are rational functions and g is not constant, then ∫ f(x) eg(x) dx is elementary if and only if there is a rational function R such that f = R′ + R g′ (and then the integral is R eg + C).

Here f = 1 and g = −x²/2 (the constant factor 1/√(2π) does not matter), so g′ = −x and the condition is R′ − x R = 1. No rational function satisfies it. If R had a pole of order m ≥ 1 at some point x0, then R′ would have a pole of order m + 1 there and x R a pole of order at most m, so R′ − x R would have a pole of order m + 1 ≥ 2 and could not be the constant 1. So R would be a polynomial. A polynomial of degree d ≥ 0 gives R′ − x R of degree d + 1 ≥ 1, because the term x R dominates, which is not a constant, and R = 0 gives 0 ≠ 1. Hence ∫ e−t²/2 dt is not elementary and neither is Φ.

The error function: an exact representation that still needs numerical methods

The error function erf(z) = (2/√π) ∫0z e−t² dt (DLMF 7.2.1) is a special function: a new name for this integral, with the complementary function erfc = 1 − erf. The substitution s = √2 t in ∫0x φ(s) ds gives exactly

Φ(x) = (1 + erf(x/√2))/2 = erfc(−x/√2)/2.

This is an exact analytical representation: Φ is written in closed form with a known function, and the properties of erf (it is odd and entire, it tends to 1, it has the Maclaurin series of DLMF 7.6.1) become properties of Φ. But erf is not elementary either (by the formula above it is elementary exactly when Φ is), and the definition by an integral does not say how to get a number: the value of erf(z) has to be computed with a finite algorithm, which is again a numerical integration, a series, a continued fraction or an approximation. Mathematical libraries do exactly this when they provide erf (JavaScript has no built-in erf, there is no Math.erf, so it has to be programmed). The approach “through erf” does not remove the numerical problem, it moves it to the computation of erf.
